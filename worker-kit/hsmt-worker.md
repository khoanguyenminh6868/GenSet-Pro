## Who runs what

- `GenBid-Bot.ps1` (Windows task "GenBid Bot", at logon, hidden) polls `/api/requests?kind=all` every 15 s (no AI, no tokens) and:
  - "Lấy tệp" → `node genbid-sync.js files --only <TBMT,...>`
  - "Sync" → `node genbid-sync.js sync`
  - Phân tích / Đối chiếu / Đối chiếu TLKT / Tạo bản tiếng Anh / Tạo HSDT tham khảo → `genbid-sync.js prep`, then `genbid-sync.js ask` (one Claude call per request or translation part: prompt + prepared data in, JSON out, no tools; Opus; translations (Tạo bản tiếng Anh, Tải PDF of a TLKT result) go first to Gemini 3.8 Flash Medium through Antigravity CLI `agy` signed in with Khoa's Google AI Pro account, no Claude tokens, and to Sonnet only when Gemini fails; up to 3 at a time; `GENBID_GEMINI_MODEL` overrides the Gemini model), then the Claude agent (`-p`, no MCP, no skills, tools Bash/Read/Write/Edit/Glob/Grep) only for folders marked AGENT (mostly scanned HSMT, unreadable HSDT files, input over 450,000 characters, or a one-call answer that was not valid JSON), then `genbid-sync.js finish`.
  - Measured 2026-10-26 (Phân tích IB2600574589, Opus): one call 153 s, 34k input tokens; agent 149 s, 9 turns, 288k input tokens. Writing the ~16k-token JSON is most of the time; Sonnet took 103 s but listed 24 technical specs instead of 45, so Opus stays.
  - On schedule (Monday to Friday at 10:00 and 15:00; a PC that was off runs once for the latest missed time that day; `.genbid-bot-schedule.json`) → `node genbid-sync.js sync --force`, no Claude session.
- The Claude desktop task "hsmt-worker" is unscheduled since 2026-10-26 (Run now still runs the same command and reports the summary).

## genbid-sync.js

- `sync [--force] [--dry]`: in a small Chromium window (headless gets no reCAPTCHA v3 token, so no results), search muasamcong for `máy phát điện` with "Chỉ tìm kiếm các thông báo mời thầu chưa đóng thầu", 50 per page, every page; read the results with `search-extract.js`; merge into `feed/current` (open tenders missing from the search stay; closed ones leave the feed and stay in `seen`). New tenders (not in feed, seen, manual, tracked, deleted): read the notice (info, chapter list, webform chapters II/III/V/VII from the viewer; prep leaves a webform chapter out when the HSMT text already has it) into `notice/<TBMT>`. Post feed, notices and `syncreq/current` done first, then fetch the files of new tenders whose name contains "máy phát điện" (others wait for Khoa's button, Khoa 2026-10-23) and of the pending "Lấy tệp" requests, then bidders and prices (`Get-GenBidBidderTargets.ps1`, `bidders-ids.js`, `bidders-extract.js`; not in a new-only Sync). New tenders are never analysed automatically (Khoa, 2026-10-24).
  - Sync mode "new" (the web's "Chỉ lấy gói mới"): only tenders published after the newest one stored are added; nothing else changes; no bidders.
  - A Sync pressed again within 10 minutes of the last one (3 minutes for the + button) gets that result back without a new search (`--force` skips this; `.genbid-sync-last.json`).
  - Checks without posting: `--dry`, `--new` (new-only), `--dry --pretend-new <TBMT>` (treat a stored tender as new).
- `files [--only K1,K2]`: for each pending file request: `files-extract.js` on the tender page, `GenBid-HSMT.ps1 -List` (VNeGP Agent, port 1234), `Publish-GenBidHsmt.ps1` (GitHub Release, release.json commit, file list and text straight to the web, state file).
- `prep --sigs "<kind>:<TBMT>|<requestedAt>,..." --out <dir>`: one folder per request with `TASK.md`, `prompt.md` (the kit's *-prompt.md), `input.md` (compacted: no layout padding, wide gaps as " | ", repeated page headers once; tender details, notice, earlier analysis for HSDT/Đối chiếu, and the HSMT text without the boilerplate chapters: Chỉ dẫn nhà thầu, Điều kiện chung, biểu mẫu hợp đồng, duplicate copies; the full text stays in `hsmt-full.txt`), translation parts `part-<i>.txt` (~60,000 characters), and for Đối chiếu the HSDT files (downloaded from the scratch bucket) with their text; Đối chiếu TLKT (Khoa, 2026-10-27) does the same with a supplier's technical proposal (scratch tlkt/<TBMT>/) against chapter V and only the technical criteria of chapter III (Mục 3. Tiêu chuẩn đánh giá về kỹ thuật; the whole chapter when that heading is not found) (the analysis's technicalSpecs only when chapter V is not there as text; no notice text), technical points only; the proposal is read as text only, never as pictures: files without text are skipped, and a proposal with no text at all is answered with an error (Khoa, 2026-10-27). Scanned files are listed with the `Render-GenBidScan.ps1` command.
- `finish --dir <dir>`: posts `result.json` / `result-<i>.json` / `notes.json` (or `error.txt` as the request's error) as analysis + analysisreq, translation + translationreq, compare + comparereq, hsdt + hsdtreq, tlkt + tlktreq, then deletes the folder (the HSDT is the company's confidential bid: it never goes into git or GitHub).
- `notice --key <TBMT>`: check one tender's notice reading, posts nothing.
- `.hsmt-worker.lock` (written by `sync` and `files`, under 3 hours old = a round is running) keeps rounds from overlapping. Exit 4 = locked. The last line printed is `SUMMARY: ...`.

## Setup on a new PC

For translations without Claude tokens: Antigravity CLI (`irm https://antigravity.google/cli/install.ps1 | iex`, then run `agy` once and sign in with Google).
